# 数据验证设计笔记

## 一、整体架构

```
请求 → 路由层（async，不处理错误） → Service层（验证+业务） → 数据库
                                         ↓ 验证失败
                                    throw 错误
                                         ↓
                                    Express 5 自动捕获
                                         ↓
                                    错误中间件统一处理
                                         ↓
                                    res.status(500).send(errHandeler(err))
```

### 各层职责

| 层 | 职责 | 不做什么 |
|----|------|---------|
| **路由层** | 接收参数、调用 Service、返回结果 | 不做验证、不处理错误 |
| **Service层** | 数据验证 + 业务逻辑 + 数据库操作 | 不处理 HTTP 响应 |
| **错误中间件** | 统一处理所有错误 | 不做业务逻辑 |

## 二、validate.js 验证器设计

### 2.1 内置验证器与自定义验证器

```javascript
// 内置验证器：validate.js 自带
presence    // 必填
type        // 类型
length      // 长度
numericality// 数值
datetime    // 日期
format      // 正则
inclusion   // 枚举

// 自定义验证器：注册到 validate.validators 上，用法和内置完全一样
validate.validators.adminExits = async function (value, options) { ... }
validate.validators.loginIdUnique = async function (value, options) { ... }
validate.validators.classExits = async function (value, options) { ... }
validate.validators.classHasNoStudent = async function (value, options) { ... }
validate.validators.bookExits = async function (value, options) { ... }
```

### 2.2 自定义验证器的两种用途

| 用途 | 验证器 | 使用场景 |
|------|--------|---------|
| **存在性检查** | `adminExits`、`bookExits`、`classExits` | 删除、更新、查询单个时验证目标是否存在 |
| **业务约束检查** | `loginIdUnique`（账号唯一）、`classHasNoStudent`（班级无学生才能删） | 添加、更新时验证业务规则 |

## 三、设计亮点

### 亮点一：更新时"可选但不可空"的验证模式

```javascript
// 添加时：字段必填（presence: true）
const addRule = {
    name: {
        presence: { allowEmpty: false },
        type: "string",
        length: { minimum: 2, maximum: 10 }
    }
}

// 更新时：字段可选（去掉 presence），但传了就不能为空
const updateRule = {
    name: {
        // 不设 presence → 字段可选
        type: "string",
        length: { minimum: 2, maximum: 10 }
        // 如果传了空字符串 ""，length 验证器会拦截
    }
}
```

**原理**：validate.js 在没有 `presence` 时，`undefined`/`null` 会跳过所有验证器；但空字符串 `""` 不会跳过，会被其他验证器（length、type、format 等）拦截。

```
不传字段（undefined）→ 跳过所有验证器 → ✅ 可选
传空字符串（""）     → 其他验证器拦截   → ❌ 不可空
传有效值             → 验证通过          → ✅
```

### 亮点二：班级删除保护

```javascript
// 删除班级前，检查是否有关联学生
validate.validators.classHasNoStudent = async function (id) {
    const count = await Student.count({ where: { ClassId: id } });
    if (count > 0) {
        return `该班级下还有 ${count} 个学生，无法删除`
    }
}
```

防止删除有学生的班级，导致数据孤立。错误信息中包含具体的学生数量，方便用户理解。

### 亮点三：管理员账号唯一性检查

```javascript
// 添加/更新管理员时，检查 loginId 是否已被占用
validate.validators.loginIdUnique = async function (loginId) {
    if (loginId === undefined || loginId === null || loginId === "") {
        return  // 空值跳过（更新时 loginId 可选）
    }
    const res = await Admin.findOne({ where: { loginId } });
    if (res) {
        return "登录账号已存在"
    }
}
```

在添加和更新时都使用这个验证器，确保 loginId 全局唯一。

### 亮点四：管理员列表不返回密码

// getAdmins 中删除密码字段
datas: rows.map((item) => {
    const result = item.toJSON()

### 亮点五：分页参数的安全验证

```javascript
const rule = {
    page: {
        presence: true,
        numericality: {
            onlyInteger: true,
            strict: false,              // 允许字符串转整数
            greaterThanOrEqualTo: 1,    // 页码最小为 1
        }
    },
    limit: {
        presence: true,
        numericality: {
            onlyInteger: true,
            strict: false,
            greaterThanOrEqualTo: 1,    // 每页至少 1 条
            lessThanOrEqualTo: 100,     // 每页最多 100 条，防止恶意请求大数据量
        }
    }
}
```

`limit` 设置上限 100，防止前端传 `limit=999999` 拖垮数据库。

### 亮点六：统一的错误处理流程

```
Service 层：验证失败 → throw（validate.async reject）
    ↓
路由层：async 函数，Express 5 自动捕获 reject
    ↓
错误中间件：统一格式化错误响应
    ↓
res.status(500).send(errHandeler(err))
```

路由层不需要写 try/catch，所有错误统一流向错误中间件。
