# 时间详解

## 时间

### utc和北京时间

**UTC（协调世界时）** 是全球统一的时间标准，所有时区都以 UTC 为基准进行偏移。

| 时间标准 | 说明 | 示例 |
|---------|------|------|
| **UTC** | 协调世界时，全球基准 | `2026-07-29 00:00:00 UTC` |
| **北京时间** | UTC+8（比 UTC 快 8 小时） | `2026-07-29 08:00:00 CST` |

#### 换算关系

```
北京时间 = UTC + 8 小时
UTC = 北京时间 - 8 小时
```

#### JavaScript 中的体现

```javascript
const date = new Date('2026-07-29T00:00:00Z');  // UTC 时间

date.toUTCString();     // "Tue, 29 Jul 2026 00:00:00 GMT"（UTC 显示）
date.toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai' });
                        // "2026/7/29 08:00:00"（北京时间显示）
```

#### 常见时区偏移

| 地区 | 时区 | 偏移 |
|------|------|------|
| 伦敦 | UTC+0 | 0 |
| 北京 | UTC+8 | +8 |
| 东京 | UTC+9 | +9 |
| 纽约 | UTC-5 | -5 |
| 洛杉矶 | UTC-8 | -8 |

### 时间戳 timestamp

时间戳是**从 1970-01-01 00:00:00 UTC 到指定时间的毫秒数**，是时间的统一数字表示。

#### 固定起点（Unix 纪元）

```
1970-01-01 00:00:00 UTC  ← 所有时间戳的"零点"
```

#### 统一机制

```
        1970-01-01 (零点)
              ↓
───┬──────────┼──────────┬──────────→
   -1天       0         +1天
   -86400000  0         86400000
```

- 零点之前的时间 → **负数**
- 零点之后的时间 → **正数**

#### JavaScript 中的时间戳

```javascript
// 获取当前时间戳
Date.now();                              // 1783046400000

// 任意时间 → 时间戳
new Date('1970-01-01').getTime();        // 0
new Date('1969-12-31').getTime();        // -86400000（负数）
new Date('2026-07-29').getTime();        // 1783046400000

// 时间戳 → 任意时间
new Date(0);                             // 1970-01-01 00:00:00
new Date(-86400000);                     // 1969-12-31 00:00:00
```

#### 时间戳的优势

1. **格式统一**：所有时间都变成一个数字，无格式差异
2. **时区无关**：基于 UTC，全球一致
3. **计算方便**：直接相减即可得到时间差

```javascript
// 计算两个时间相差多少天
const d1 = new Date('2026-07-29').getTime();
const d2 = new Date('2026-01-01').getTime();
const diffDays = (d1 - d2) / (1000 * 60 * 60 * 24);  // 209 天
```

### 对于服务器的影响

#### 1. 服务器时间统一使用 UTC

服务器通常配置为 **UTC 时区**，原因：

| 原因 | 说明 |
|------|------|
| **避免时区混乱** | 多地部署的服务器时间一致 |
| **日志统一** | 日志时间戳全球可比对 |
| **数据库存储** | 推荐用 UTC 存储时间 |

```javascript
// 服务器端推荐：存储 UTC 时间
const utcTime = new Date().toISOString();
// "2026-07-29T00:00:00.000Z"  ← 带有 Z 后缀表示 UTC
```

#### 2. 数据库时间存储建议

```javascript
// ❌ 不推荐：存储本地时间字符串
db.save({ createTime: '2026-07-29 08:00:00' });  // 时区不明确

// ✅ 推荐：存储 UTC 时间或时间戳
db.save({ createTime: new Date().toISOString() });  // UTC 字符串
db.save({ createTime: Date.now() });                // 时间戳
```

#### 3. Node.js 服务器示例

```javascript
// 服务器统一用 UTC 处理，返回给客户端时再转换
app.get('/api/time', (req, res) => {
    const serverTime = new Date();  // 服务器时间（UTC）
    res.json({
        timestamp: serverTime.getTime(),        // 时间戳（统一）
        utc: serverTime.toISOString(),           // UTC 字符串
    });
});
```

### 对于客户端的影响

#### 1. 客户端负责时区转换

服务器返回 UTC 时间，客户端根据用户本地时区显示：

```javascript
// 服务器返回 UTC 时间
const serverData = { createTime: '2026-07-29T00:00:00.000Z' };

// 客户端转换成本地时间显示
const localTime = new Date(serverData.createTime).toLocaleString();
// 北京用户看到："2026/7/29 08:00:00"
// 纽约用户看到："7/28/2026, 8:00:00 PM"
```

#### 2. 浏览器时区处理

```javascript
// 获取用户本地时区
const userTimezone = Intl.DateTimeFormat().resolvedOptions().timeZone;
// "Asia/Shanghai"

// 按用户时区格式化显示
new Date().toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai' });
// "2026/7/29 08:00:00"
```

#### 3. 常见问题：时区导致的"日期偏移"

```javascript
// 服务器存储：2026-07-29T00:00:00.000Z（UTC 零点）
const date = new Date('2026-07-29T00:00:00.000Z');

// 北京时间显示（UTC+8）
date.toLocaleDateString('zh-CN');  // "2026/7/29"（同一天）

// 纽约时间显示（UTC-5）
date.toLocaleDateString('en-US');  // "7/28/2026"（前一天！）
```

⚠️ **这就是为什么服务器应该统一用 UTC，由客户端负责本地化显示**。

#### 4. 前端最佳实践

```javascript
// 1. 从服务器接收 UTC 时间
const rawTime = '2026-07-29T00:00:00.000Z';

// 2. 用库（如 dayjs）处理显示
import dayjs from 'dayjs';
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';

dayjs.extend(utc);
dayjs.extend(timezone);

// 3. 按用户时区显示
dayjs.utc(rawTime).local().format('YYYY-MM-DD HH:mm:ss');
// 北京用户："2026-07-29 08:00:00"
```


## Moment.js 与 Day.js 对比笔记

## 一、两者的关系

Day.js 是 **Moment.js 的轻量级替代品**，可以理解为"Moment.js 的现代化重写版"。

```
Moment.js（老前辈，功能全但臃肿）
    ↓ 启发
Day.js（继承 API，瘦身 + 不可变 + 插件化）
```

### 1.1 核心对比

| 对比项 | Moment.js | Day.js |
|--------|-----------|--------|
| **API 设计** | 原创设计 | 几乎完全模仿 Moment.js |
| **体积** | 约 67KB（gzip 后约 17KB） | 约 7KB（gzip 后约 2KB） |
| **可变性** | 可变（mutable） | 不可变（immutable） |
| **状态** | 已停止维护（legacy） | 活跃维护中 |
| **链式调用** | 支持 | 支持 |

### 1.2 Moment.js 官方态度

> "We now generally consider Moment to be a legacy project in maintenance mode. It is not dead, but it is indeed done."
> —— Moment.js 官方

Moment.js 官方自己推荐迁移到其他库。

## 二、API 相似性

Day.js 的 API **95% 与 Moment.js 相似**，迁移成本极低：

```javascript
// Moment.js 写法
moment().format('YYYY-MM-DD');
moment().add(7, 'days');

// Day.js 写法（几乎一样）
dayjs().format('YYYY-MM-DD');
dayjs().add(7, 'day');  // 注意：'days' → 'day'
```

### 2.1 主要差异点

#### 参数单位不同

```javascript
// Moment.js（复数）
moment().add(7, 'days');
moment().startOf('months');

// Day.js（单数）⚠️
dayjs().add(7, 'day');
dayjs().startOf('month');
```

#### 不可变性差异

```javascript
// Moment.js（可变 - 危险！）
const m1 = moment();
const m2 = m1.add(1, 'day');
console.log(m1 === m2);           // true（同一个对象被修改了）
console.log(m1.format());          // 明天！（原对象变了）

// Day.js（不可变 - 安全）
const d1 = dayjs();
const d2 = d1.add(1, 'day');
console.log(d1 === d2);            // false（新对象）
console.log(d1.format());          // 今天（原对象不变）
```

## 三、Day.js 插件系统

Day.js 核心精简，很多功能通过**插件按需加载**，而 Moment.js 是全量内置。

### 3.1 插件使用方式

```javascript
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';

dayjs.extend(relativeTime);  // 注册插件
dayjs().fromNow();           // "几秒前"
```

### 3.2 插件与 Moment.js 原生功能对应关系

Day.js 的插件**基本上就是为了补齐 Moment.js 原生功能**而存在的：

| Moment.js 原生 | Day.js 插件 | 功能说明 |
|----------------|-------------|----------|
| `moment().fromNow()` | `relativeTime` | 相对时间（"3天前"） |
| `moment.duration()` | `duration` | 时长计算 |
| `moment.utc()` | `utc` | UTC 时间 |
| `moment.tz()` | `timezone` | 时区处理 |
| `moment().weekday()` | `weekday` | 星期设置 |
| `moment().isoWeek()` | `isoWeek` | ISO 周 |
| `moment().week()` | `weekOfYear` | 年中第几周 |
| `moment(str, format)` | `customParseFormat` | 自定义格式解析 |
| `moment().isLeapYear()` | `isLeapYear` | 闰年判断 |
| `moment().quarter()` | `quarterOfYear` | 季度 |
| `moment().isBetween()` | `isBetween` | 区间判断 |
| `moment().isSameOrBefore()` | `isSameOrBefore` | 相同或之前 |
| `moment().isSameOrAfter()` | `isSameOrAfter` | 相同或之后 |
| `moment().min()` / `max()` | `minMax` | 最值比较 |

### 3.3 常用插件示例

#### relativeTime（相对时间）

```javascript
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';
dayjs.extend(relativeTime);

dayjs().fromNow();                    // "几秒前"
dayjs('2026-01-01').from(dayjs());    // "7 个月前"
dayjs().to(dayjs('2026-12-31'));      // "5 个月内"
```

#### duration（时长）

```javascript
import duration from 'dayjs/plugin/duration';
dayjs.extend(duration);

dayjs.duration(100, 'minutes');       // 100 分钟的时长
dayjs.duration({ days: 1, hours: 2 });
const d = dayjs.duration('P1Y2M3D');  // ISO 8601 格式
d.asHours();                          // 总小时数
```

#### timezone（时区）

```javascript
import utc from 'dayjs/plugin/utc';
import timezone from 'dayjs/plugin/timezone';
dayjs.extend(utc);
dayjs.extend(timezone);

dayjs.tz('2026-07-29', 'Asia/Shanghai');
dayjs().tz('America/New_York').format();
dayjs.tz.guess();                     // 猜测当前时区
```

#### customParseFormat（自定义解析）

```javascript
import customParseFormat from 'dayjs/plugin/customParseFormat';
dayjs.extend(customParseFormat);

// 核心库不支持自定义格式解析，需要插件
dayjs('29/07/2026', 'DD/MM/YYYY');
dayjs('2026年07月29日', 'YYYY年MM月DD日');
```

## 四、Day.js 常用 API 速查

### 4.1 核心内置 API

```javascript
// 解析
dayjs();                          // 当前时间
dayjs('2026-07-29');              // 字符串解析
dayjs(1669500000000);             // 时间戳解析
dayjs(new Date());                // Date 对象

// 格式化
dayjs().format();                 // 默认格式
dayjs().format('YYYY-MM-DD HH:mm:ss');

// 获取/设置
dayjs().year();
dayjs().month();
dayjs().date();
dayjs().day();                    // 星期几
dayjs().hour();
dayjs().minute();
dayjs().second();

// 操作
dayjs().add(7, 'day');
dayjs().subtract(1, 'month');
dayjs().startOf('month');
dayjs().endOf('day');

// 比较
dayjs().isBefore(dayjs('2026-12-31'));
dayjs().isAfter(dayjs('2026-01-01'));
dayjs().isSame(dayjs(), 'day');
```

### 4.2 特色 API

```javascript
// diff - 计算差值
const d1 = dayjs('2026-07-29');
const d2 = dayjs('2026-01-01');
d1.diff(d2);              // 毫秒差（默认）
d1.diff(d2, 'day');       // 天数差
d1.diff(d2, 'hour', true); // 浮点数（带小数）

// daysInMonth - 当月天数
dayjs('2026-02-01').daysInMonth();  // 28（非闰年）
dayjs('2024-02-01').daysInMonth();  // 29（闰年）

// isBetween - 区间判断
dayjs().isBetween(dayjs('2026-01-01'), dayjs('2026-12-31'));
```

## 五、核心结论

### 5.1 三句话总结

1. **Day.js = Moment.js 的功能拆解版**，把"全家桶"变成了"自助餐"
2. **API 95% 相似**，迁移成本低，主要差异是单位用单数 + 不可变对象
3. **插件即 Moment.js 原生功能**，几乎一一对应，按需加载

### 5.2 迁移建议

| 场景 | 推荐方案 |
|------|---------|
| 新项目 | 直接用 Day.js |
| 老项目体积优化 | Moment → Day.js（API 几乎兼容） |
| 需要 ISO 周历、复杂时区 | 仍可用 Moment.js（功能更全） |
| 现代项目（ESM） | Day.js（原生 ESM 支持） |

### 5.3 设计理念对比

```javascript
// Moment.js：一次性全部加载（67KB）
import moment from 'moment';
// 所有功能都可用，但体积大
moment().fromNow();
moment.duration(100, 'minutes');

// Day.js：用多少加载多少（核心 2KB）
import dayjs from 'dayjs';
import relativeTime from 'dayjs/plugin/relativeTime';

dayjs.extend(relativeTime);  // 只加载需要的功能
dayjs().fromNow();
```

**Day.js 的设计哲学**：核心精简 + 插件扩展 + 按需付费，让用户只为用到的功能买单。
