# node模块化细节

## 模块的查找

1. 绝对路径
```js
require('C:/Users/uuy/Desktop/nodejsServe/node核心/2.node模块化细节/模块1');
```

2. 相对路径./或../
    - 相对于当前模块的目录
    - 会转换为绝对路径
    - 加载模块时，会根据绝对路径查找模块
```js
require('./模块1');
```
3. 模块路径
    - 检查是否是内置模块，如fs,http等
    - 检查当前目录中的node_modules目录
    - 检查上一级目录中的node_modules目录
    - 转换为绝对路径
    - 加载模块时，会根据绝对路径查找模块
    - 如果找不到模块，会报出错误
    - 语法如下
```js
require('模块1');
```
4. 关于后缀名
    - 导入模块时，可以省略后缀名
    - 例如require('模块1')会自动补全后缀名，回依次查找模块1.js,模块1.json,模块1.node,模块1.mjs.如果都没有找到，会报出错误。

5. 关于文件名
    - 如果仅提供目录，不提供文件名，则自动寻找目录下的index.js文件
        - 查找流程如下
        - 先把该目录名认定为一个文件。比如是一个src目录。会转换为src.js,src.json,src.node,src.mjs.如果都没有找到.进入下一步
        - 查找目录下的index.js文件。如果找到，会加载该文件。找不到回依次查找index.json,index.node,index.mjs.如果都没有找到，会报出错误。
    - package.json的main字段
        - 表示包的默认入口
        - 导入或执行包时若仅提供目录，会根据main补全入口
        - 默认值为index.js,如果目录名中没有index.js文件，会报出错误
        - 如果package.json中指定了main字段，会根据main字段的值查找模块
        - 如果没有指定main字段，会根据目录名查找模块
        - 如果目录名中没有index.js文件，会报出错误

## module对象与require函数

module对象记录了当前模块的信息
- 模块的路径
- 模块的依赖
- 模块的导出对象

require函数用于加载模块
- 语法如下
```js
require('模块路径');
```
- 例如require('./src');
- 会require('./src/index.js'); 如果没有index.js文件，会报出错误
- 内置方法
    - require.resolve('模块路径');
        - 会返回模块的绝对路径
        - require.resolve('./src');
        - 会返回C:/Users/uuy/Desktop/nodejsServe/node核心/2.node模块化细节/src/index.js

> 当执行一个模块或使用require时，会将模块放置在一个函数环境中

## module.exports 与 exports 的区别

### 核心问题：为什么直接赋值与添加属性返回的模块对象不一样？

当执行一个模块时，Node.js 内部会执行以下伪代码逻辑：

```js
function require(modulePath) {
    // 1. 创建 module 对象，初始化 module.exports 为空对象
    module.exports = {};
    
    // 2. exports 变量指向 module.exports 引用的同一个对象
    const exports = module.exports;
    
    // 3. 将模块代码放入 _temp 函数中执行
    function _temp(module, exports, require, __dirname, __filename) {
        // 用户的模块代码写在这里
        exports.c = 3;           // 方式1：给 exports 添加属性
        module.exports = {       // 方式2：给 module.exports 重新赋值
            a: 1,
            b: 2,
        };
    }
    
    // 4. 执行模块代码
    _temp.call(module.exports, module, exports, require, module.path, module.filename);
    
    // 5. 返回 module.exports（关键！）
    return module.exports;
}
```

### 执行流程分析

**阶段1：初始状态**
- `module.exports = {}` 创建一个空对象
- `const exports = module.exports` 让 `exports` 和 `module.exports` **指向同一个对象**

**阶段2：添加属性**
- `exports.c = 3` 在共享对象上添加属性
- 此时 `exports` 和 `module.exports` 仍然指向同一个对象

**阶段3：关键分叉点（重新赋值）**
- `module.exports = {a: 1, b: 2}` 给 `module.exports` **重新赋值**了一个全新对象
- `exports` 仍然指向旧对象（包含 `c: 3`）
- `module.exports` 指向新对象（`{a: 1, b: 2}`）

**阶段4：最终返回**
- `return module.exports` 返回的是新对象，而非 `exports` 指向的旧对象

### 两种方式对比

| 方式 | 代码示例 | 结果 |
|------|---------|------|
| **添加属性** | `module.exports.a = 1; module.exports.b = 2` | 保持同一引用，`exports` 和 `module.exports` 始终同步 |
| **重新赋值** | `module.exports = {a: 1, b: 2}` | 破坏引用关系，两者分道扬镳 |

### 结论

- Node.js 最终返回的是 `module.exports`，而非 `exports`
- 若要导出对象，**优先使用 `module.exports`**，避免引用断裂问题
- 若使用 `exports`，只能添加属性（`exports.xxx = value`），不能重新赋值（`exports = {...}`）
