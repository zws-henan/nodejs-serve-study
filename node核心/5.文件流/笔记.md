# 文件流

fs.readFile()在读取文件时会把所有内容放到内存中,如果文件很大,会占用很多内存.因此,我们通常会使用流来读取较大文件.

## 文件流

`流`是一种数据传输机制,它允许我们以块的形式读取数据,而不是一次读取所有数据.流也是有方向的,只能从一个方向流动.
可分为三种类型:可读流(数据从源头流向内存)、可写流(数据从内存流向源头)、双工流(可读可写).

> 为什么需要流式?

1. 读取大文件时,可以避免占用很多内存.
2. 可以实现文件的实时处理,例如:
   - 实时压缩文件
   - 实时加密文件
   - 实时发送文件
3. 其他介质与内存的数据规模不同,例如:
   - 硬盘数据规模大于内存
   - 网络数据规模大于内存
4. 其他介质和内存的数据处理能力不同,例如:
   - 硬盘数据处理能力小于内存
   - 网络数据处理能力小于内存

文件流就是指内存数据和数据文件之间的传输.

**文件可读流的创建**

1. 创建一个可读流
   - 可以使用fs.createReadStream(path,options)方法创建一个可读流
     - path: 文件路径
     - options: 可选的,用于配置流的行为
        - encoding:编码方式
        - start:开始读取的位置
        - end:结束读取的位置
        - highWaterMark:缓冲区的大小，即每次读取的数量。默认是64kb。即64*1024个字节
        - autoClose:是否自动关闭流。默认是true
        - fd:文件描述符。默认是null
        - flags:文件标志。默认是'r'
        - mode:文件模式。默认是0o666
    - 返回一个可读流(readStream)对象
        - 事件：rs.on(事件名，回调函数)
            - data: 当有数据可读时触发
                - 注册data事件后，才会真正开始读取
                - 每次读取highWaterMark大小的数据
                - 回调函数中会附带读取到的数据
            - end: 当读取完成时触发
            - error: 当发生错误时触发
            - close: 当流关闭时触发
                - 可以通过fs.close(fd)方法关闭流
                - 或文件读取完毕后,会自动关闭流
            - open: 当流打开成功时触发
        - rs.pause()方法: 暂停读取数据。会触发pause事件
        - rs.resume()方法: 继续读取数据。会触发resume事件
        - rs.destroy()方法: 销毁流
        - rs.pipe(writeStream)方法: 管道流
            - writeStream: 可写流对象
            - 将可读流连接到可写流
            - 返回可写流对象
            - 该方法旨在解决背压问题。背压问题是指,可读流读取数据的速度快于可写流写入数据的速度,导致可写流缓冲区溢出,从而导致可读流暂停读取数据。

**创建文件可写流**

> 创建一个可写流
   - 可以使用fs.createWriteStream(path,options)方法创建一个可写流
     - path: 文件路径
     - options: 可选的,用于配置流的行为
        - encoding:编码方式
        - flags:文件标志。默认是'w'表示覆盖写入文件。'a'表示追加写入文件。'wx'表示创建文件并写入数据。
        - mode:文件模式。默认是0o666
        - autoClose:是否自动关闭流。默认是true
        - fd:文件描述符。默认是null
        - start:开始写入的位置。默认是0
        - highWaterMark:缓冲区的大小，即每次写入的数量。默认是16kb。即16*1024个字节
   - 返回：Writable的子类writeStream对象
      - 事件：ws.on(事件名，回调函数)
        - error: 当发生错误时触发
        - close: 当流关闭时触发
        - open: 当流打开成功时触发
        - drain: 当写入队列清空时触发
      - ws.write(data)方法: 写入数据
         - data: 要写入的数据。字符串或Buffer对象
         - 返回一个布尔值
            - true:写入通道没有被填满，接下来的数据可以直接写入，无需等待。写入通道的大小与highWaterMark一致
            - false:写入通道被填满，接下来的数据将进入写入队列，等待写入通道清空。注意背压问题。因为写入队列是内存中的数据是有限的。
      - ws.end(data)方法: 结束写入数据
         - data是可选的，会自动关闭文件
      - ws.destroy()方法: 销毁流
