# http模块

http模块建立在net模块的基础上,用于更加方便地创建http服务器。无需手动管理socket对象。无需手动组装http请求和响应。无需手动解析请求头和请求体。无需手动设置响应头和响应体。

它不是Ajax模块。脱离了浏览器Ajax是不存在的,并且脱离了浏览器后就不存在跨域问题。

## 使用http模块

1. 引入http模块
    -  `http = require('http')`
    -  `import http from 'http'`
    - http是一个对象,包含了创建服务器的方法createServer()
2. http.request(url,options,callback)
    - url: 请求地址
    - options: 请求选项
    - callback: 请求成功后的回调函数
        - res: 响应对象(IncomingMessage)
    - 返回一个可写流对象(ClientRequest)
        - 可以通过向流写入内容发送数据
        - 可以通过监听流的内容获取数据
        - 需要调用request.end()结束请求
3. http.createServer(options,requestListener)
    - options: 服务器选项(可选)
    - requestListener: 请求监听器回调函数
        - req: 请求对象(IncomingMessage)
        - res: 响应对象(ServerResponse)
    - 返回一个Server对象
    - 不传options时,直接传requestListener
    - requestListener会在每次HTTP请求到来时执行
4. server.listen(port,hostname,backlog,callback)
    - port: 监听端口
    - hostname: 监听地址(可选,默认0.0.0.0)
    - backlog: 连接队列长度(可选)
    - callback: 监听成功后的回调函数(可选)
        - 无参数
        - 只在服务器启动成功时执行一次

## 使用https模块

### https协议

https协议是http协议的加密版本,用于创建安全的http服务器。因为http协议是明文传输,所以存在安全问题。比如截取到http请求,可以查看请求体和响应体
加密后,保证**数据不被窃听和篡改**。这涉及到一些密码学知识。

**对称加密**：
- 对称加密是指使用相同的密钥进行加密和解密。
- 加密和解密速度快,但是密钥管理困难。
- 例如AES加密。

**非对称加密**：
- 分为公钥和私钥
    - 公钥加密的数据可以被私钥解密
    - 私钥加密的数据可以被公钥解密
- 非对称加密是指使用不同的密钥进行加密和解密。
- 加密和解密速度慢,但是密钥管理简单。
- 例如RSA加密。

**对称加密与非对称加密流程**

> 首先a持有对称加密的key2和公钥，b持有公钥和私钥。

a向b通信(不太安全的通信过程)

1. b把公钥传给a

2. a用公钥加密key2,并发送给b

3. b用私钥解密key2,这样b就可以使用key2加密解密数据,至此只有双方持有key2密钥，这样就可以进行安全的数据传输了

4. a发送一个key2加密的数据给b。b可以使用key2解密数据。并可以使用key2加密数据发送给a

> 但是在第一次通信中有些问题。因为公钥可能会被截获,导致数据被篡改。因此需要引入第三方机构（CA：证书颁发机构）。用它来保证公钥的合法性。

> 证书颁发流程

#### CA 的角色

CA（Certificate Authority，证书颁发机构）就像一个"数字公安局"，负责颁发和管理数字证书，证明某个公钥确实属于某个实体（网站、服务器、个人等）。

#### CA 运转流程

1. **密钥生成**：服务器生成一对密钥
   - 私钥：自己保存，绝对不能泄露
   - 公钥：可以公开给任何人

2. **证书申请**：服务器把公钥和身份信息（域名、公司名称等）发送给 CA

3. **CA 验证身份**：验证申请者的身份（域名所有权、公司合法性等）

4. **CA 签发证书**：验证通过后，CA 用自己的私钥对服务器的公钥和身份信息进行签名，生成数字证书

5. **证书分发**：服务器拿到证书后，在 HTTPS 连接时发送给客户端

#### 数字证书内容

```
数字证书:
├── 服务器的公钥
├── 服务器的身份信息（域名、有效期等）
└── CA 的数字签名（用 CA 私钥加密的摘要）
```

#### CA 如何保证数据安全

**核心原理：非对称加密 + 数字签名**

1. **身份验证**：浏览器用 CA 的公钥验证证书签名
   - 验证通过：确认这是真的服务器
   - 验证失败：拒绝连接（可能是中间人攻击）

2. **密钥交换**：身份验证通过后，双方协商一个对称密钥
   - 浏览器生成随机数（对称密钥）
   - 用服务器的公钥加密这个随机数
   - 发送给服务器，服务器用私钥解密

3. **数据加密传输**：双方用对称密钥加密后续通信

#### 为什么中间人攻击无效

| 步骤 | 中间人能否做到 | 说明 |
|------|---------------|------|
| 获取服务器公钥 | ✅ 能 | 公钥本来就是公开的 |
| 验证公钥真实性 | ❌ 不能 | 需要 CA 的私钥签名 |
| 伪造 CA 签名 | ❌ 不能 | CA 的私钥高度保密 |

**关键**：中间人可以获取公钥，但无法伪造 CA 的签名。没有有效的 CA 签名，浏览器不会信任这个公钥。

#### 数字签名的作用

数字签名是对公钥和身份信息的完整性证明：

```
CA 的签名过程：
1. 对证书内容做哈希运算，得到摘要
2. 用 CA 的私钥加密摘要，得到签名

浏览器验证过程：
1. 对证书内容做哈希运算，得到摘要A
2. 用 CA 的公钥解密签名，得到摘要B
3. 比较摘要A和摘要B：
   - 相同：证书未被篡改，公钥可信
   - 不同：证书被篡改，拒绝信任
```

#### CA 的层级结构

```
根 CA（Root CA）
├── 中间 CA（Intermediate CA）
│   └── 服务器证书（如百度）
└── 中间 CA
    └── 个人证书
```

- 根 CA：最顶层，公钥预装在浏览器和操作系统中
- 中间 CA：由根 CA 授权，可以签发证书
- 服务器证书：最终颁发给网站的证书

#### 总结

**公钥公开 ≠ 身份可信**

- 公钥是公开的，任何人都可以获取
- CA 的作用是证明"这个公钥确实属于这个服务器"
- 中间人攻击失败的原因：无法伪造 CA 的数字签名
- 浏览器信任的不是公钥本身，而是 CA 对"公钥归属"的证明


### https模块

https模块是http模块的加密版本,用于创建https服务器。
https模块需要安装证书,否则会报错。
证书可以使用openssl工具生成。
```bash
openssl req -x509 -newkey rsa:2048 -nodes -out cert.pem -out key.pem -365
```
