# Node.js 生命周期

## 一、事件循环概述

Node.js 的事件循环是其异步编程模型的核心，负责调度和执行异步操作的回调函数。它以单线程方式运行，但通过非阻塞 I/O 实现高并发。

事件循环的核心思想：**调用栈清空后，轮询处理各类异步任务队列**

## 二、libuv 线程池与事件循环的关系

Node.js 的非阻塞 I/O 依赖 **libuv** 库实现，事件循环与线程池协同工作：

### libuv 线程池

**角色**：执行耗时的 I/O 操作（文件系统、DNS 查询、加密等）

**特性**：
- 默认创建 **4 个工作线程**
- 可通过环境变量 `UV_THREADPOOL_SIZE` 调整（最大 128）
- 线程池是全局共享的

### 工作流程

```
JavaScript 主线程（事件循环）
        │
        ▼
┌──────────────────────────────┐
│     调用异步 API              │
│  (fs.readFile, dns.lookup)   │
└──────────────────┬───────────┘
                   │ 提交到线程池
                   ▼
┌──────────────────────────────┐
│     libuv 线程池              │
│  (4个工作线程执行实际I/O)     │
└──────────────────┬───────────┘
                   │ I/O完成
                   ▼
┌──────────────────────────────┐
│     Poll 阶段队列             │
│  (回调被加入队列等待执行)      │
└──────────────────┬───────────┘
                   │
                   ▼
        JavaScript 主线程
        (执行回调函数)
```

### 线程池适用场景

| 操作类型 | 是否使用线程池 | 说明 |
|----------|---------------|------|
| 文件系统操作 | ✅ | `fs.readFile`, `fs.writeFile` 等 |
| DNS 查询 | ✅ | `dns.lookup`, `dns.resolve` 等 |
| 加密操作 | ✅ | `crypto.pbkdf2`, `crypto.randomBytes` |
| 压缩操作 | ✅ | `zlib` 模块 |
| 网络操作 | ❌ | 使用操作系统的非阻塞套接字 |

## 三、事件循环的六个阶段

### 阶段 1：Timers（计时器阶段）

**角色**：执行 `setTimeout()` 和 `setInterval()` 的回调函数

**执行机制**：
- 检查所有到期的计时器回调
- 按时间顺序执行，直到队列为空或达到系统限制
- `setTimeout(fn, 0)` 并非立即执行，而是进入下一个 tick

**示例**：
```javascript
setTimeout(() => {
  console.log('timers phase');
}, 0);
```

**注意**：
- 计时器回调的执行时机是"最早可能时间"，而非精确时间
- 如果上一阶段耗时过长，计时器可能会延迟执行

---

### 阶段 2：Pending Callbacks（待处理回调阶段）

**角色**：执行 I/O 操作的回调，包括：
- TCP 错误回调（如连接失败）
- 文件 I/O 错误回调
- 某些系统调用的回调

**执行机制**：
- 处理上一轮循环中延迟到当前轮的 I/O 回调
- 主要处理网络相关的错误回调

---

### 阶段 3：Idle, Prepare（空闲、准备阶段）

**角色**：仅内部使用，对用户代码不可见

**执行机制**：
- 执行内部的空闲任务
- 为下一轮 poll 阶段做准备

---

### 阶段 4：Poll（轮询阶段）⭐ 核心阶段

**角色**：等待新的 I/O 事件，执行 I/O 相关回调

**执行机制**：
1. **执行队列中的 I/O 回调**：处理文件系统、网络等 I/O 操作的回调
2. **轮询新事件**：如果队列为空，进入等待状态，直到：
   - 有新的 I/O 事件到达
   - 有到期的计时器
   - 有 setImmediate 回调待执行

**两种子状态**：
- **有回调待执行**：依次执行所有 I/O 回调
- **无回调待执行**：进入等待状态，直到新事件触发

**示例**：
```javascript
const fs = require('fs');
fs.readFile('file.txt', (err, data) => {
  console.log('poll phase - I/O callback');
});
```

---

### 阶段 5：Check（检查阶段）

**角色**：执行 `setImmediate()` 的回调函数

**执行机制**：
- 在 poll 阶段结束后立即执行
- `setImmediate` 总是在当前轮事件循环的 I/O 回调完成后执行

**示例**：
```javascript
setImmediate(() => {
  console.log('check phase');
});
```

**与 setTimeout 的区别**：
```javascript
// 两者执行顺序不确定（取决于进入事件循环的时间点）
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));

// 在 I/O 回调中，setImmediate 总是先于 setTimeout(0)
fs.readFile('file.txt', () => {
  setTimeout(() => console.log('timeout'), 0);
  setImmediate(() => console.log('immediate')); // 先执行
});
```

---

### 阶段 6：Close Callbacks（关闭回调阶段）

**角色**：执行关闭相关的回调函数

**执行机制**：
- 处理关闭事件，如 `socket.destroy()`、`stream.destroy()` 的回调
- 专门处理资源关闭相关的回调，并非兜底执行所有回调

**示例**：
```javascript
const socket = new net.Socket();
socket.on('close', () => {
  console.log('close callbacks phase');
});
socket.destroy();
```

## 六、微任务（Microtasks）与宏任务（Macrotasks）

### 微任务队列

微任务包括：
- `process.nextTick()` ⭐ 优先级最高（独立于微任务队列，更快）
- `Promise.then()` / `Promise.catch()` / `Promise.finally()`
- `queueMicrotask()`

**执行时机**：
- **Node.js 11+**：每个阶段内的**每个宏任务执行完毕后**都会清空微任务队列（与浏览器行为一致）
- **Node.js 10 及之前**：每个阶段执行完毕后清空微任务队列

### 宏任务队列

每个阶段对应的任务队列：
- Timers: `setTimeout`, `setInterval`
- Poll: I/O 回调
- Check: `setImmediate`
- Close: 关闭回调

**执行顺序示例**：
```javascript
console.log('1. sync');

setTimeout(() => console.log('2. setTimeout'), 0);

Promise.resolve().then(() => console.log('3. promise'));

process.nextTick(() => console.log('4. nextTick'));

setImmediate(() => console.log('5. setImmediate'));

// 输出顺序：1 → 4 → 3 → 2 → 5
```

## 七、process.nextTick() 的特殊地位

**角色**：在当前操作完成后立即执行，优先级高于所有其他异步任务

**机制**：
- 不属于事件循环的六个阶段
- 在每个阶段切换前执行
- 可能导致事件循环无法进入 poll 阶段（如果递归调用）

**使用场景**：
- 确保回调在当前同步代码执行完后立即执行
- 在构造函数中触发事件（避免实例未完成初始化）

## 八、Node.js 进程生命周期事件

### 事件列表

| 事件 | 触发时机 | 用途 |
|------|----------|------|
| `beforeExit` | 事件循环为空且没有其他待处理任务 | 可以异步操作使进程继续运行 |
| `exit` | 进程即将退出 | 只能执行同步操作 |
| `uncaughtException` | 未捕获的异常 | 最后机会处理异常 |
| `unhandledRejection` | Promise 拒绝未处理 | 处理未捕获的 Promise 拒绝 |
| `SIGINT` | 收到中断信号（Ctrl+C） | 优雅关闭 |
| `SIGTERM` | 收到终止信号 | 优雅关闭 |

### 示例：优雅关闭
```javascript
process.on('SIGINT', () => {
  console.log('收到 SIGINT，开始优雅关闭');
  server.close(() => {
    console.log('服务器已关闭');
    process.exit(0);
  });
});

process.on('exit', (code) => {
  console.log(`进程即将退出，退出码: ${code}`);
});
```

## 九、关键要点总结

1. **事件循环是单线程的**：所有 JavaScript 代码在同一线程执行
2. **非阻塞 I/O**：I/O 操作由底层线程池处理，完成后触发回调
3. **阶段顺序固定**：Timers → Pending → Idle → Poll → Check → Close
4. **微任务优先**：每个阶段结束后先清空微任务队列
5. **nextTick 最快**：`process.nextTick()` 优先级最高
6. **setImmediate vs setTimeout**：在 I/O 回调中，setImmediate 总是先执行

---

## 十、实践建议

- **避免同步阻塞**：长时间运行的同步代码会阻塞事件循环
- **合理使用微任务**：`process.nextTick()` 用于紧急任务，`Promise.then()` 用于普通微任务
- **注意递归 nextTick**：可能导致事件循环无法进入 poll 阶段
- **优雅关闭**：监听 SIGINT/SIGTERM 信号，处理资源释放
